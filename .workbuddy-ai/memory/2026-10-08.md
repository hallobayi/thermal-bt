# 2026-10-08 — Refactor + kompatibilitas tablet Android

## Yang dikerjakan

Refactor `rawthermal-js` untuk keterbacaan + perbaikan kompatibilitas tablet
Android. Versi dinaikkan 1.1.0 → 1.2.0 (perubahan string Intent).
`npm run verify` → **49 uji lulus**, build bersih.

## Refactor (tanpa mengubah API publik)

- `config.js`: tambah `MODES` (android-intent/browser/fallback/browser-text)
  sebagai satu-satunya sumber string mode; `normalizePackageName()` dipisah.
  `withDefaults()` tetap satu-satunya tempat normalisasi opsi.
- `intent.js`: `buildViewIntent(url, packageName, ctx)` — argumen posisional
  ketiga diganti objek `{ base, browserFallbackUrl }`; penyusunan parameter
  Intent lewat array, bukan perangkaian string.
- `index.js`: `launch()` memakai `MODES.*`, `fallbackTarget` dihitung sekali
  untuk kedua jalur; `MODES` diekspor di API publik.
- `dom.js`: `clickAnchor()` dipakai ulang oleh `openUrl` dan `clickIntent`;
  `OBJECT_URL_TTL_MS` menggantikan angka 60000; `tryWindowOpen()` dipisah.
- Duplikasi `getWindow()` di `platform.js` dan `dom.js` **disengaja** dan
  dikomentari: tiap modul harus berdiri sendiri di bundel browser.

## Perbaikan bug (temuan analisis)

1. **`window.open(url, target, "noopener")` selalu dilaporkan gagal.**
   Browser mengembalikan `null` kalau features memuat `noopener`, sehingga
   `!!ref` false → `ok: false` untuk tab yang sebenarnya terbuka. Sekarang
   features tidak dipakai; opener diputus manual via `ref.opener = null`.
   Uji lama tidak menangkap ini karena window tiruan selalu mengembalikan `{}`.
2. **Nota `printText` tampil kecil di tablet.** Dokumen tanpa
   `<meta name="viewport">` dirender dengan layout viewport 980px.
   Dibuktikan di Edge headless + emulasi tablet 800×1280: lama → viewport 980,
   scale 0.816; baru → viewport 800, scale 1.
3. **Tablet mode "situs desktop" tidak terdeteksi** karena UA tidak menyebut
   Android dan hanya `ontouchstart` yang dicek. Sekarang `maxTouchPoints`
   dipakai lebih dulu. `userAgentData.mobile` TIDAK dipakai (nilainya `false`
   di tablet).
4. **Intent gagal tanpa jejak** kalau aplikasi target tidak terpasang.
   Ditambah `S.browser_fallback_url` (Chrome for Android), diisi dari
   `fallbackUrl || url`. Tanpa `fallbackUrl`, hasilnya tetap URL PDF absolut.
5. **Anchor `intent://` diletakkan off-screen**, bukan `display:none` — WebView
   Android lama tidak menjalankan klik pada elemen yang tidak dirender.
6. Anchor juga jatuh ke `document.documentElement` kalau `document.body` belum
   ada (skrip di `<head>`).

## Catatan perubahan perilaku yang perlu diberitahu

- String Intent sekarang berakhiran `;S.browser_fallback_url=…;end`. Uji yang
  mengunci bentuk string itu ikut diperbarui (memang disengaja).
- `printText` sekarang membawa viewport + `@page{size:58mm auto}` dan
  **membuka dialog cetak otomatis** (`autoPrint`, default `true`). Bisa
  diblokir CSP halaman pemanggil; dokumen tetap terbuka.
- Trade-off `S.browser_fallback_url`: kalau filter activity aplikasi target
  tidak cocok dengan URI http(s) (lihat MEMORY.md), Chrome akan membuka PDF di
  browser alih-alih diam. Itu lebih baik daripada gagal senyap, tetapi artinya
  Intent ini belum bisa dianggap "langsung cetak" sampai diuji di perangkat.

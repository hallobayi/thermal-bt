## Yang dikerjakan

Refactor penuh `rawthermal-js` (helper PWA → Raw Thermal Android), dari satu
berkas 150 baris menjadi modul-modul kecil + build + test.

- `src/config.js` — DEFAULTS + `withDefaults()` (satu-satunya tempat normalisasi opsi)
- `src/platform.js` — `isAndroid(win)`, murni, bisa dites tanpa browser

### Perbaikan bug (temuan analisis)

1. `npm run build` memanggil `build.js` yang tidak ada → sekarang ada.
2. `print()` cek `typeof === "string"` setelah `if (!options)` (urutan keliru).
3. Opsi dari `print()` bocor ke request → `withDefaults()` hanya meloloskan
   kunci yang ada di `DEFAULTS`.
4. `printText()` punya dua cabang `window.open` identik → disatukan.
5. Object URL `printText` tidak pernah dilepas → memory leak; sekarang
   di-revoke lewat `revokeObjectUrl`.
6. Nama `buildViewIntent` dobel (internal + publik) → shadowing dihapus.
7. `printBase64(base64, options)` dua parameter tak terpakai → dihapus.
8. `openInNewTab` ada di DEFAULTS tapi tidak pernah dibaca → sekarang dipakai.
9. `packageName` kosong menghasilkan `intent://…package=;` → sekarang ditolak.
10. Kegagalan popup-blocker ditelan senyap → hasil melaporkan `ok: false`.

### Pelajaran build (mahal, jangan diulang)

`build.js` mengekstrak body factory dari tiap modul. Dua pendekatan tekstual
GAGAL dan keduanya melaporkan sukses tanpa peringatan:

- `lastIndexOf("});")` — `Object.keys(...).forEach(function (k) {…});` di dalam
  body juga berakhir `});` → modul terpotong di tengah, sisa baris bocor jadi
  kode liar di bundel.
- `indexOf("{", marker)` — `{` di dalam default parameter ikut terhitung.

Solusi yang dipakai: penanda eksplisit `/* @body-start */` dan `/* @body-end */`
di setiap modul sumber. **Jangan hapus penanda itu.**

Dua bug runtime yang juga menyamar sebagai "kode benar":

- Entry factory dipanggil dengan `config, platform, …` padahal modul hanya
  tersedia sebagai `window.RawThermal*` → `config is not defined`. Argumen
  sekarang dibaca dari `global.RawThermal*`.
- Modul IIFE tidak menugaskan hasilnya (`(function () {…})();` tanpa
  `global.X =`) → entry membaca `undefined`. Sekarang setiap modul wajib
  `global.RawThermalX = (function () {…})();`.

Selain itu, `vm.createContext(win)` TIDAK membagikan objek host kembali —
nilai yang script set di `window` harus dibaca lewat `vm.runInContext(...)`.
Tanpa itu semua tampak `undefined` dan seolah ada bug yang tidak ada.

## Investigasi target: aplikasi syofyanzuhad/raw-thermal

Dibaca langsung dari sumber di GitHub (commit Jan 2026). Ini **bukan** aplikasi
Raw Thermal dari Play Store — ini APK open source karya syofyanzuhad,
"Rawbt alternative", dibangun dengan **Capacitor + Vue 3**.

Yang penting untuk library ini:

- **Package**: `com.rawthermal.app`
- **AndroidManifest** (`android/app/src/main/AndroidManifest.xml`): MainActivity
  (`exported=true`, `singleTask`) menerima
  - `ACTION_VIEW` untuk `application/pdf` dan `image/*`
  - `ACTION_SEND` untuk PDF dan gambar
  - Tapi **tidak ada** MIME `text/plain`, dan **tidak ada custom scheme**
    (`rawbt:` tidak ada), juga tidak ada `android:scheme` sama sekali.
- **Bluetooth**: `BluetoothService.ts` memakai
  `@capacitor-community/bluetooth-le` → **BLE GATT**, bukan Bluetooth Classic
  SPP. UUID yang dicoba: `000018f0…` (printer service) + `00002af1…`,
  alternatif `49535343-fe7d-4ae5-8fa9-9fafd205e455`.
- **ESC/POS**: encoder ada di dua tempat —
  `android/…/printservice/EscPosEncoder.kt` dan `src/services/escpos/EscPosEncoder.ts`.
- **PrintService**: `ThermalPrintService.kt` adalah Android PrintService asli
  (`android.printservice.PrintService`, `BIND_PRINT_SERVICE`). Alurnya: terima
  PrintJob → render ke bitmap (`ThermalPdfRenderer`) → dithering
  (`ImageDithering`) → kirim via Bluetooth. Lebar kertas: 384 dot (58mm) / 576
  dot (80mm).
- **Jika printer belum dikonfigurasi**: job disimpan ke cache lalu aplikasi
  dibuka dengan `PendingPrintJob`.
- **Kanal dari luar**: hanya `MainActivity.handlePrintIntent()` yang mengecek
  `intent.getStringExtra("action") == "SETUP_PRINTER_FOR_PRINT"`; selain itu
  tidak ada deep link/Intent API yang didokumentasikan.

### Konsekuensi

Aplikasi ini **tidak menerima URL atau Base64 dari browser**. Ia menerima
dokumen lewat `ACTION_SEND`/`ACTION_VIEW` (file) atau lewat Android print
framework. Jadi `intent://…#Intent;type=application/pdf;package=com.rawthermal.app;end`
kemungkinan besar **tidak memicu cetak** — tidak ada README/API handoff di
sumbernya. Ini perlu diverifikasi di perangkat nyata sebelum diandalkan.

## Printer: iware ZJ-5809 II (Shenzhen Zijiang)

- **ESC/POS didukung** (listing pabrikan: "Print Comand: ESC/POS",
  "ESC / POS / STAR compatible command set")
- 58mm, 384 dot/baris, 203dpi, font 12×24 & 24×24
- Interface USB + **Bluetooth 4.0**, disebut mendukung **SPP** (dan IRCOMM)
- 7.4V/2000mAh

Catatan penting: dukungan ESC/POS di printer **bukan** yang menghambat cetak
dari browser. Hambatannya ada di sisi platform — lihat MEMORY.md.
